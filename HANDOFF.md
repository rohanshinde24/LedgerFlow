# LedgerFlow — Handoff

Living status document. Rewritten as phases land. See `SPEC.md` for the canonical design.

## Current state

**P0 complete. P1 complete. P2 partial. P3 complete.**

The deterministic core runs with no LLM anywhere. On top of it, `agent-service` investigates the
payments and transactions the deterministic tiers could not settle, and every proposal is
re-validated deterministically before it can be accepted. P2 adds one write path: an idempotent,
audited financial operation. P3 is a frozen two-seed benchmark with per-case results.

Builds: `mvn -B test` → **57 tests green**. `agent-service` → **40 tests green**. `npm run build` → clean.

## Running it

```bash
docker start ledgerflow-postgres                      # or: docker compose -f infra/docker-compose.yml up -d
cd financial-core && LEDGERFLOW_GENERATE_DATASET=true mvn spring-boot:run   # :8080
cd web && npm install && npm run dev                  # :3000

cd agent-service && python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/uvicorn ledgerflow_agent.main:app --port 8010
```

Model provider defaults to **Ollama** (`qwen2.5:7b`) to hold the $0 constraint. Sampling is pinned:
`model_temperature=0.0`, `model_seed=20250311`. Set `LEDGERFLOW_MODEL_PROVIDER=anthropic` with a real
key for the Anthropic path — **that path is written but has never been executed**. Treat it as
unverified.

Reconciliation is scored over **unapplied payments only**. A payment already matched at generation
time leaves no open invoice to find, so escalating it is the only defensible answer while the label
still names the invoice it is matched to. Scoring those measured nothing and depressed recall to
0.447; the scope fix is what makes the figure mean anything. Dev's 14/16 matches SPEC §7
independently.

### The engineering finding

Precision against capability-call count, held-out:

| capability calls | n | answered | correct | precision |
|---|---|---|---|---|
| 1 | 8 | 8 | 8 | 1.000 |
| 2 | 16 | 16 | 16 | 1.000 |
| 4 | 4 | 3 | 0 | **0.000** |
| 6 | 1 | 1 | 1 | 1.000 |

Every wrong answer on the held-out set happened at 4 capability calls, and all of them are
`AMBIGUOUS_MERCHANT` (0/4: 3 wrong, 1 abstained). Every other difficulty class was perfect, including
`INTERNAL_TRANSFER` 24/24. Long investigations do not find more; they go wrong. The fix is stopping
behaviour, not a higher iteration ceiling.

### Reliability

Seven failures injected around the only code path that mutates financial state, each verified by
reading Postgres afterwards: duplicate request, concurrent duplicate delivery (8 racing callers),
retry after lost response, process restart, transient dependency failure, distinct key on a settled
subject, audit-trail immutability.

Reproduce: `mvn -f financial-core test -Dtest=FinancialOperationFaultInjectionTest`.

That suite caught a real ordering bug: the "already categorized" check ran *before* the operation key
was claimed, so a concurrent retry under the same key got an invariant error instead of replaying.
The claim now happens first, so the unique constraint arbitrates the race.

## Known limitations

- **Held-out scored higher than development.** Expected — dev holds the cases that were inspected and
  iterated on, so it is the harder set by construction. The held-out figure may be optimistic against
  genuinely novel data.
- **Reproducibility is partial.** Sampling is pinned and two identical 14-case policy runs produced 0
  outcome flips, but the full 73/77-case sweep has been run once per seed and its reproducibility is
  unverified.
- **Latency is not a clean measurement** — local Ollama on a machine also running unrelated
  containers. Deterministic figures are trustworthy; agent p95 (213s) reflects contention.
- **Escalation recall rests on n=2 per seed.** Too small to lean on. Transaction escalation recall is
  **undefined**: every transaction carries a correct account code, so no transaction genuinely needs a
  human, and any transaction abstention is a missed answer rather than a correct refusal.
- **One observed failure in 48 payment calls**: a transient 502 from core unreachability. It exposed an
  asymmetry — the reconciliation path surfaces core errors as 502, while the transaction path degrades
  to tier-3 escalation. The transaction behaviour is the correct one.
- `AMBIGUOUS_MERCHANT` is 0/4 held-out. This is the live failure mode.

## Non-obvious things worth knowing

- **Assigned identifiers change `save()` semantics.** Entities carry application-assigned UUIDs, so
  Spring Data issues `merge()` and returns a *managed copy*. Mutating the original after saving
  silently does nothing. `SyntheticDatasetGenerator.persist()` applies allocations *before* the
  first `save`. This bit once and produced silently-zero `amount_paid`.
- **`char(3)` fails Hibernate schema validation** — Postgres reports it as `bpchar`. Migrations use
  `varchar(3)` with `@Column(length = 3)` on every `Currency` field.
- **Dataset generation must run outside the test transaction**: `@TestInstance(PER_CLASS)` with a
  non-static `@BeforeAll`, and `@Transactional(readOnly = true)` only on tests that traverse lazy
  associations.
- **The dataset ends 2025-12-31, not "today".** `web/lib/reportingWindow.ts` anchors reports there.
- **Ollama rejects tool calls for models whose chat template lacks a tools section** — original
  llama3, gemma2, gemma3 fail with "does not support tools". Use qwen2.5 or llama3.1+.
- **Ollama's default temperature is 0.8.** Before it was pinned, two identical 14-case runs flipped 5
  of 12 comparable outcomes. Any benchmark taken without pinned sampling is noise.
- **The Testcontainers Postgres is shared per JVM.** A test that creates its own fixtures pollutes
  other tests that call `findAll()` unscoped. `SyntheticDatasetIntegrationTest` now scopes its
  assertions to its own business.
- **`localhost` resolves to `::1` first on macOS.** A Docker container bound to `*:8010` shadows a
  local service on `127.0.0.1:8010`. The benchmark addresses services by IPv4 literal for this reason.
- Agent tests use `ScriptedModelClient` plus an `httpx.MockTransport` core, so the suite needs no
  network and no API key. Prefer extending that over mocking internals.
